# 与上游插件的功能对照

上游 [`MeteorNOX/DeepSeek-Balance-Whale-Widget`](https://github.com/MeteorNOX/DeepSeek-Balance-Whale-Widget)
是跑在 **DSH Web / Electron 宿主**里的插件：宿主能给它会话事件、凭据服务、文件系统、浏览器 DOM。
设备端只有一块 240×135 的屏、一个键盘、一张 SD 卡、一个 WiFi。下面逐条说明哪些能搬、怎么搬、哪些搬不动。

## 一、已移植（口径对齐）

| 上游功能 | 设备端实现 | 对齐方式 |
|---|---|---|
| 余额（`GET /user/balance`） | `net_link.cpp::fetchBalance()` | 同一 URL、同一 `Bearer` 鉴权；`balance_infos[0]` 取数，多币种时优先 CNY（上游取 `[0]`，这里更友好一点） |
| 赠金 / 充值余额分列 | 主屏只显总余额，冒泡与管理页列出三个值 | 同字段 `granted_balance` / `topped_up_balance` |
| 今日已用（余额观测口径） | `ledger.cpp` | 直接移植 `accounting.mjs`：下降累计消费、上升单独记充值、1e-8 定点、按北京时间分日、`partialDay` 判定（10 分钟缺口） |
| 按密钥指纹分本 | `scopeFromKey()` FNV-1a 64 → 16 位十六进制 | 上游用 API key 的 sha256 前 24 位；语义相同（换 key = 换一本账，旧本保留、不跨本相加） |
| 峰谷定价 | `pricing.cpp` | `PEAK_HOURS` 9-12/14-18、周末谷价（2026-08-23 起）、法定节假日谷价（2026-09-19 起）、空闲价 = 高峰价一半；价目表 `BASE_PRICE` / `PRO_PRICE` 原样搬 |
| 时段倒计时 | 主屏底部 + 冒泡第 3 项 | `nextPeakChangeAt()` 与 `isPeakTime()` 同源（上游前端也算这个，但由宿主下发节假日清单；设备端把表编进固件） |
| 点击序列（首次泡 → 队列 → 随机台词） | `bubbles.cpp` | 队列顺序对齐（余额 → 今日 → 峰谷 → 随机），30 秒不点回到第 1 项；随机台词**不连续重复**、带权重（上游是「并列加权选择」的简化版） |
| 每个事件一个音效 | `sound.cpp` | 合成音（按键 / 完成 / 报错），支持 SD 上的自定义 wav 覆盖 |
| 原子写账本 | `ledger.cpp::saveToFile()` | 写 `.tmp` → `remove` → `rename`（上游也是原子写入 + 备份） |
| 证书校验 | `root_ca.h` + `WiFiClientSecure::setCACert` | `api.deepseek.com` 的链根是 DigiCert Global Root G2；上游在宿主里走 Node 的信任链 |
| 只读接口不产生费用 | 同 | 余额查询是 GET，不消耗 token |

## 二、换了个实现（能力等价或更简单）

| 上游 | 设备端 | 说明 |
|---|---|---|
| 配置存 `$DSH_HOME/.dshw-*.json`（多个文件） | SD 卡 `/dswhale/config.json` + `ledger.json` | 设备端只需两处状态；**没有卡时**配置退回 NVS |
| 凭据服务（不落配置文件） | config.json 明文 / NVS | ESP32 没有等价的凭据服务；文档里明确写了「key 在卡上是明文」以及缓解办法 |
| 余额 25 秒 TTL + 前端 60 秒轮询 | 单一 `refresh_sec`（默认 60 秒） | 设备端没有多客户端，去掉一层缓存 |
| 泡泡「模块化排版」（文本/图片/随机/余额模块，最多 6 行 6 模块） | 4 类固定内容 + 多行文本 | 240×135 上做拖拽排版编辑器不现实；保留了「内容可自定义」的**结果**（文案在 `bubbles.cpp`） |
| 余额校正（手动填累计到账金额） | ❌ 未做 | 见下一节 |
| 余额预警 / 今日预算 | ❌ 未做 | 需要键盘输入金额；留作后续（可走 config.json） |
| 吸附 / 拖拽 / Q 弹 / 镜像翻转 | ❌ 不适用 | 挂件在网页里才需要「摆放」，设备上鲸鱼就固定在左半边 |

## 三、搬不动的（宿主能力，设备端没有）

| 上游功能 | 为什么搬不动 |
|---|---|
| **每轮对话消耗**（真实 usage：input/cache/output/reasoning） | 数据来自 DSH 的会话事件。设备端不在 DSH 进程里，看不到任何一轮的 token。**替代方案**：设备只做余额观测；想按 token 记账只能继续用网页挂件。 |
| **DSH 账号登录态取余额**（不配 API key） | 那是 DSH 自己持有的账号令牌与会话服务，插件只是「调 DSH 的服务」。设备端没有这个服务，**必须自备 API key**。 |
| Codex 本地会话统计 | 要读本机 `$CODEX_HOME` 下的 jsonl。设备端没有那些文件。 |
| 34 个厂商模板 / 自定义 API / 订阅额度窗口 | 需要一整套面板 + 密钥管理 + 任意 HTTP 端点。设备端只做 DeepSeek 一家；要多家就得把设备变成通用 HTTP 客户端 + 配置编辑器，超出「掌上余额挂件」的范围。 |
| 音频片段裁剪 / 试听 / 图库管理 | 需要浏览器 UI 与文件系统。设备端**只支持**「把一个 wav 拷到固定路径」。 |
| 提问 / 授权提示音、任务结束音（随 DSH 事件） | 同样是宿主事件。设备端的「完成音」只在手动刷新/开机取到余额时响。 |
| 反向代理 / 局域网访问 / 信任栅栏 | 那是**服务端**的安全设计（谁能访问 `/dsh-whale/*`）。设备端是客户端，不监听端口，因此没有这层问题——代价是配置只能拔卡改。 |

## 四、后续可以做的（按性价比排序）

1. **余额预警 / 今日预算**：把阈值写进 `config.json`，超了就冒泡 + 响铃。（不需要键盘输入，改动很小）
2. **余额校正**：账本里加 `correction` 字段（上游有完整公式），设备端用一个简单的数字输入（键盘上的数字行）即可。
3. **设备端配置界面**：现在只能靠 SD 卡改 `wifi.pass` / `api_key`，做一个逐字符输入的编辑页会更完整。
4. **AP 配网门户**：首次开机起一个 SoftAP + 网页表单，手机填 WiFi 与 key。
5. **多厂商**：把 `pricing.cpp` 旁边加一个 `providers.cpp`（端点 + 字段路径 + 币种），配置里选厂商。
6. **单元测试**：把 `money` / `pricing` / `ledger` 拿出来在主机上编译，用 `platformio native` 或一个简易 Makefile 跑。
7. **上游跟进**：DeepSeek 调价或新增节假日时同步 `pricing.cpp`（表在文件顶部，改一处即可）。

## 五、移植时的两个坑（给后来者）

1. **`timegm()` 在 arduino-esp32 3.x 里没有**。日期换 epoch 用 Howard Hinnant 的 `days_from_civil`（`ledger.cpp` 里那段），别引 libc。
2. **余额接口的数字是字符串**（`"110.00"`，不是 `110.00`）。用 `.as<double>()` 也能work，但直接拿 `const char*` 再 `strtod` 更稳、更省内存，`money::parse()` 就是这个用途。
